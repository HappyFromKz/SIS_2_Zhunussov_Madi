# BUG-001: Any authenticated user can read another user's cart

**Severity:** High (data exposure / broken access control) — pending confirmation of intended design
**Environment:** https://api.practicesoftwaretesting.com, 2026-11-22
**Found by:** automated test `tests/06-api-cart.spec.ts` › "a user cannot read another user's cart"

## Steps to reproduce
1. Register user B, log in, get token B.
2. As user B: `POST /carts` → cart id `<cartB>`; add a product with `POST /carts/<cartB>`.
3. Register user A, log in, get token A.
4. As user A: `GET /carts/<cartB>` with `Authorization: Bearer <tokenA>`.

```bash
curl -H "Authorization: Bearer <tokenA>" https://api.practicesoftwaretesting.com/carts/<cartB>
```

## Expected
401, 403 or 404. User A must not see the contents of user B's cart.

## Actual
200 OK, response body contains user B's cart items.

## Notes
- Reproduced twice (initial run + retry).
- Question for analyst: are carts intentionally anonymous (guest carts accessible by id)?
  If yes, this is a specification gap: the spec should state it explicitly; cart ids then act as secrets.
- Related observation: `POST /carts/{id}` with `quantity: "abc"` returns
  404 "Resource not found" instead of 422 with a validation message.
